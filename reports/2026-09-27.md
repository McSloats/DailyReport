### CVE-2026-35273 — Oracle PeopleSoft PeopleTools, unauthenticated RCE (CVSS 9.8) — renewed mass exploitation
ShinyHunters (UNC6240) is now bypassing WAF rules that mitigated this deserialization flaw by percent-encoding part of the vulnerable `/PSEMHUB/` request path; many WAFs match the literal path while Oracle WebLogic decodes and routes it anyway. Google/Mandiant confirmed a renewed wave of web-shell and SIDEEYE-backdoor deployments across higher education, tech, healthcare, agriculture, transportation, and government targets, expanding beyond the flaw's original academic-sector victims.
**Fix:** Confirm you're on Oracle's patched PeopleTools release (not just WAF-mitigated); hunt for `Ple64.exe`/SIDEEYE indicators and unexpected `/PSEMHUB/` traffic with encoded path segments.
Source: https://www.bleepingcomputer.com/news/security/shinyhunters-uses-waf-bypass-trick-in-oracle-peoplesoft-attacks/

## Critical CVEs (NVD, CVSS ≥ 9.0)

### CVE-2026-97163 — UP plugin for Joomla, unauthenticated remote code install (CVSS 10.0)
Versions 5.0.0–5.2.0 and 6.0.0–6.0.29 let an unauthenticated request trigger an on-demand download of "action" code from the maintainer's GitHub repo into a plugin directory that Joomla then executes — with TLS certificate verification disabled during the fetch, so a network-positioned attacker can substitute a malicious archive. Public PoC and payload code are already on GitHub.
**Fix:** Update to UP 5.2.1 / 6.1.0 immediately.
Source: https://www.strix.ai/cve/CVE-2026-97163

### CVE-2026-100716 — Froxlor server-admin panel, path traversal → host root (CVSS 9.9)
The customer data-export cron fails to validate an intermediate path segment (an off-by-one error), so an authenticated low-privilege customer with export enabled can point an export at a symlinked path; the root-owned cron's recursive `chown` then hands the attacker ownership of arbitrary host directories (e.g. `/etc`), yielding full host root and cross-tenant compromise. Disclosed September 26; no public exploit confirmed yet.
**Fix:** Upgrade to Froxlor 2.3.12.
Source: https://www.strix.ai/cve/CVE-2026-100716

### CVE-2026-100717 — Froxlor server-admin panel, config injection via subdomain redirect (CVSS 9.9)
An authenticated customer with subdomain-create rights can smuggle a CR/LF payload into a redirect URL's userinfo field; it passes validation and is written verbatim into the generated nginx/Apache vhost config, which Froxlor then reloads as root — letting the injected directives hijack responses or read local files server-wide. Incomplete fix for a prior advisory; disclosed September 26.
**Fix:** Upgrade to Froxlor 2.3.12.
Source: https://www.strix.ai/cve/CVE-2026-100717

### CVE-2026-100741 — hMailServer, JScript eval injection (CVSS 9.8)
Versions 6.0.0–6.3.3 on Windows fail to escape a backslash preceding an apostrophe in user-supplied data (e.g. an SMTP/POP3/IMAP password), letting a remote unauthenticated attacker break out of a string literal and run arbitrary JScript inside the mail server process — reaching command execution via `WScript.Shell`. Requires event scripting enabled with JScript as the script language (off/VBScript by default), so exposure depends on configuration.
**Fix:** Check whether event scripting + JScript is enabled; watch for a hMailServer patch and disable the feature if not needed. Linux builds and VBScript-only configs are unaffected.
Source: https://www.strix.ai/cve/CVE-2026-100741

## General News

### UpGuard: 16,326 Supabase databases left publicly readable, exposing user data from "vibe-coded" apps
Tables created via SQL, API calls, or migration files in Supabase — the path AI coding agents and vibe-coding tools take when scaffolding a schema — don't get Row Level Security enabled by default, unlike tables made through the dashboard's Table Editor. Researchers found names, addresses, phone numbers, passwords, auth tokens, OTP codes, and in some cases payment data readable with zero authentication across services in the US, India, the Philippines, Africa, and Canada.
**Fix:** Any Supabase-backed app not built through the dashboard should have RLS policies audited immediately — the fix is enabling RLS and writing table policies, not infrastructure changes.
Source: https://cybernews.com/news/16000-supabase-databases-exposed/
