**CVE-2026-42016 / CVE-2026-42018 — JFrog Artifactory: Chained Auth Bypass to Admin Takeover**
CVSS 8.1 / 7.5 individually, but chained they hand full admin control. CVE-2026-42018 leaks an internal anonymous-user token to unauthenticated callers even when anonymous access is disabled; CVE-2026-42016 then lets that low-privilege token be swapped for an admin-scoped one by checking only the token's signature/issuer, not its scope. Added to CISA KEV Sept 12. **Fix:** patch to the latest Artifactory release and rotate any tokens issued during the exposure window.

## 🟠 Critical CVEs (NVD, CVSS ≥ 9.0)

**CVE-2026-78006 / CVE-2026-78159 — StellarWP "The Events Calendar" (WordPress): Unauthenticated RCE**
CVSS 9.8 each. Two independent bypasses of the plugin's widget-safety check lead to arbitrary PHP object instantiation and code execution: CVE-2026-78006 abuses PHP's pre-parse magic-method firing combined with a forged integrity hash to reach `unserialize()` via an unauthenticated commenter's own pending-comment view; CVE-2026-78159 exploits insufficient validation of a widget's "classes" map to bypass the same safety check. Affects versions up to 6.17.4 (78006) and 6.17.3 (78159). One of the most widely installed WordPress event-management plugins — no confirmed in-the-wild exploitation yet, but expect scanning quickly given the plugin's install base. **Fix:** update to the patched version as soon as StellarWP publishes it; in the interim, restrict/moderate public comments on event pages.
Source: https://www.strix.ai/cve/CVE-2026-78006

**Passkey/SSO-themed social engineering feeds ShinyHunters and Helix extortion campaigns**
Microsoft's Sept 9 research details Storm-3121 and Storm-3032 (feeding ShinyHunters/Falcon and Helix extortion, respectively) calling or texting employees' personal phones, posing as IT help desks warning that a passkey/MFA/SSO update is urgently needed. Victims are pushed to lookalike Microsoft login pages where adversary-in-the-middle or device-code flows steal credentials and session tokens — no actual passkey enrollment is attempted. Active since May 2026. **Mitigation:** train staff that IT will never request passkey/MFA changes via unsolicited calls or SMS; enforce phishing-resistant auth and restrict device-code flow where possible.
