## Actively Exploited / CISA KEV

### CVE-2026-67276 + CVE-2026-86060 — MikroTik RouterOS "MikroTrick" SSH auth-bypass chain (CVSS 9.2)
RouterOS's SSH public-key check compares only the RSA key's type and modulus, not its exponent (CVE-2026-67276) — so an attacker who knows a valid authorized key's modulus can forge a signature with exponent 1 and open an admin SSH session without ever holding the private key. Chained with an argument-parsing bug in the SSH login path (CVE-2026-86060), it escalates straight to full device control. CERT Polska has tracked exploitation against internet-exposed RouterOS SSH services since September 2, with attackers planting rogue accounts (commonly suffixed "-2") to keep persistence. **Fix:** update to RouterOS 7.24.2, 7.23.4, 6.49.21, or 7.25beta3; until patched, take SSH off the internet-facing interface and audit user lists for unrecognized accounts.
Source: https://thehackernews.com/2026/09/attackers-hijack-mikrotik-routers.html

## Critical CVEs (NVD, CVSS ≥ 9.0, not yet confirmed exploited)

### CVE-2026-10196 — Mail Mint WordPress plugin (getwpfunnels) unauthenticated PHP object injection to RCE (CVSS 9.8)
Mail Mint (up to 1.31.0) deserializes untrusted input in its `handle_form_submission` handler without validation; combined with a PHP object-injection (POP) gadget chain already present in the plugin, an unauthenticated attacker can submit a crafted form to a public endpoint and achieve remote code execution — no login or prior access required. **Fix:** update Mail Mint to the latest patched release (1.23.1 addressed part of the chain; confirm the current fix is installed) and scan the site for unexpected PHP files.
Source: https://radar.offseq.com/threat/cve-2026-10196-cwe-502-deserialization-of-untrusted-data-in-getwpfunnels-mail-mint-email-marketing-d56b6ada4f5a1ed0

## Vendor Advisories

### CVE-2026-6471 — PostgreSQL "PostGREShell" logical-replication privilege escalation to RCE (CVSS 7.2, 12 years old)
Missing authorization in PostgreSQL's logical decoding lets any account holding just the `REPLICATION` attribute — routine for backup tools, CDC pipelines, and standby servers — pick an arbitrary shared library as its "output plugin." The server loads it with `dlopen()` and runs it as the OS account running Postgres: full code execution and a path to a permanent superuser backdoor, without ever needing the superuser role to start. The flaw has existed since logical decoding shipped in Postgres 9.4 (2014). Below the CVSS 9.0 critical threshold, but included given the near-universal deployment base and severity of impact. **Fix:** upgrade to PostgreSQL 18.6, 17.11, 16.15, 15.19, or 14.24; meanwhile strip `REPLICATION` from accounts that don't need it and lock down `pg_hba.conf` replication entries to known hosts.
Source: https://www.securityweek.com/12-year-old-postgresql-vulnerability-enables-database-server-takeover/
